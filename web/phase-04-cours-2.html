Git et le contrôle de version

Git enregistre l'historique de ton code, te permet de revenir en arrière, de travailler par étapes, et de publier ton travail. C'est l'outil que tout développeur utilise au quotidien — et la porte d'entrée vers GitHub, où DevYoon lui-même est hébergé.

Ce que Git résout

Sans contrôle de version, on finit avec des dossiers nommés projet-final, projet-final-v2, projet-final-v2-vraiment — et aucun moyen de savoir ce qui a changé entre les versions. Git enregistre chaque étape de ton travail sous forme d'historique, avec la possibilité de revenir à n'importe quel point.

Définition

Un dépôt Git (repository, ou "repo") est un dossier suivi par Git : chaque modification qu'on choisit d'enregistrer devient un commit, un point dans l'historique auquel on peut toujours revenir.

Les trois zones de Git

Git distingue trois états pour tes fichiers : ceux que tu as modifiés, ceux que tu as préparés pour le prochain commit (staging), et ceux déjà enregistrés dans l'historique.

git status # l'état actuel : rien à espérer de mieux comme réflexe git add fichier.html # ajoute ce fichier au staging git add . # ajoute tous les fichiers modifiés git commit -m "Ajoute la page d'accueil" # enregistre dans l'historique git log # affiche l'historique des commits
Bon réflexe

git status ne fait courir aucun risque — c'est la commande à lancer sans hésiter, tout le temps, pour savoir exactement où on en est avant d'agir.

Démarrer un dépôt

cd mon-projet git init # transforme ce dossier en dépôt Git git add . git commit -m "Premier commit"

Le fichier .gitignore

Certains fichiers ne doivent jamais être suivis par Git : dépendances installées, fichiers de configuration locaux, secrets. On les liste dans un fichier .gitignore, à la racine du projet.

# .gitignore node_modules/ .env .DS_Store

Publier sur GitHub

Ton dépôt local vit sur ta machine. Pour le rendre accessible en ligne (et le sauvegarder), on le connecte à un dépôt distant — GitHub est la plateforme la plus utilisée.

git remote add origin https://github.com/ton-compte/mon-projet.git git branch -M main # nomme la branche principale "main" git push -u origin main # envoie le code sur GitHub
Authentification

Depuis 2021, GitHub n'accepte plus le mot de passe classique pour git push en HTTPS — il faut un token d'accès personnel (Settings → Developer settings → Personal access tokens sur GitHub), utilisé à la place du mot de passe.

Les branches, en bref

Une branche est une ligne de développement indépendante — utile pour tester une idée sans toucher au code stable de main.

git branch # liste les branches git checkout -b feature/menu # crée et bascule sur une nouvelle branche git checkout main # revient sur main

Pour ce projet, une seule branche (main) suffit largement — les branches deviendront utiles plus tard, en travaillant à plusieurs ou sur des fonctionnalités plus longues.

À retenir
  • Git enregistre l'historique du projet par commits, à travers trois zones : dossier, staging, historique.
  • git status, git add, git commit -m forment le cycle de base à répéter sans arrêt.
  • .gitignore exclut les fichiers qui ne doivent jamais être suivis.
  • git remote add + git push publient le dépôt local sur GitHub, avec un token plutôt qu'un mot de passe.
  • Les branches isolent un développement en cours — utile dès qu'on travaille à plusieurs ou sur une fonctionnalité longue.
