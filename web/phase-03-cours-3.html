Événements et interactivité

Tu sais écrire du JavaScript et manipuler le DOM. Il manque la pièce qui relie les deux à l'utilisateur : les événements — ce qui déclenche ton code au bon moment, pas avant.

Le principe d'un événement

Un événement est quelque chose qui se produit sur la page — un clic, une touche pressée, un formulaire envoyé. JavaScript peut "écouter" un événement précis sur un élément précis, et exécuter une fonction quand il se produit.

L'élément écouté ne fait rien tant que l'événement ne se produit pas — ton code attend, prêt à réagir.

addEventListener

addEventListener() est la méthode standard pour écouter un événement : elle prend le nom de l'événement, et la fonction à exécuter quand il se produit.

const bouton = document.querySelector("#mon-bouton"); bouton.addEventListener("click", () => { console.log("Le bouton a été cliqué !"); });

Les événements les plus courants

  • click — un clic (bouton, lien, n'importe quel élément)
  • input — la valeur d'un champ change, à chaque frappe
  • submit — un formulaire est envoyé
  • keydown — une touche du clavier est enfoncée
  • DOMContentLoaded — la page a fini de charger (utile pour lancer ton code au bon moment)

L'objet event

La fonction appelée reçoit automatiquement un objet décrivant l'événement — souvent nommé event ou e. Deux usages reviennent très souvent : connaître l'élément concerné, et empêcher un comportement par défaut.

const formulaire = document.querySelector("form"); formulaire.addEventListener("submit", (event) => { event.preventDefault(); // empêche le rechargement de la page console.log("Formulaire intercepté, traité en JS"); }); document.querySelector(".liste").addEventListener("click", (event) => { console.log("Élément cliqué :", event.target); // l'élément exact touché });
Définition

event.target est l'élément exact sur lequel l'événement s'est produit. event.preventDefault() annule le comportement par défaut du navigateur (recharger la page sur un submit, suivre un lien, etc.).

Délégation d'événements

Plutôt que d'attacher un écouteur à chaque élément d'une liste (y compris ceux ajoutés plus tard), on attache un seul écouteur au conteneur parent, et on regarde quel enfant a été touché via event.target.

const liste = document.querySelector("ul.taches"); liste.addEventListener("click", (event) => { if (event.target.tagName === "LI") { event.target.classList.toggle("terminee"); } });

Cette technique fonctionne même pour des éléments ajoutés au DOM après la mise en place de l'écouteur — un avantage direct pour une liste de tâches où on ajoute des éléments dynamiquement.

Assembler le tout

Un exemple complet qui combine sélection, création d'élément et événement — la structure exacte que ton projet va réutiliser.

const input = document.querySelector("#nouvelle-tache"); const bouton = document.querySelector("#ajouter"); const liste = document.querySelector("#liste-taches"); bouton.addEventListener("click", () => { if (input.value.trim() === "") return; const item = document.createElement("li"); item.textContent = input.value; liste.appendChild(item); input.value = ""; // vide le champ après ajout });
À retenir
  • Un événement déclenche une fonction au moment où il se produit — clic, saisie, envoi de formulaire...
  • addEventListener(type, fonction) est la méthode standard pour écouter un événement.
  • event.target identifie l'élément touché, event.preventDefault() annule le comportement par défaut.
  • La délégation (écouteur sur le parent) gère aussi les éléments ajoutés après coup.
  • Sélection + création d'éléments + événements, combinés, suffisent à construire une vraie application interactive.
