Node.js et Express

Jusqu'ici, tout ton code s'exécutait dans le navigateur de la personne qui visite la page. Cette phase change de côté : on écrit le code qui tourne sur un serveur, celui qui répond quand un navigateur — ou ton appli React — lui demande quelque chose.

JavaScript en dehors du navigateur

Node.js est un environnement qui exécute du JavaScript en dehors d'un navigateur — sur un serveur, sur ta machine, n'importe où. C'est ce qui permet d'écrire le code back-end (côté serveur) dans le même langage que tout ce que tu as appris jusqu'ici.

Définition

Node.js exécute du JavaScript hors navigateur. npm (Node Package Manager) est son gestionnaire de paquets — il installe des bibliothèques tierces, comme Express, avec une simple commande npm install.

Express : simplifier la création d'un serveur

Node.js seul permet déjà de créer un serveur, mais de façon verbeuse. Express est une bibliothèque qui simplifie énormément cette tâche — définir des routes devient quelques lignes.

// npm install express const express = require("express"); const app = express(); app.get("/", (req, res) => { res.send("Bonjour depuis le serveur !"); }); app.listen(3000, () => { console.log("Serveur lancé sur http://localhost:3000"); });

Lancé avec node server.js, ce code démarre un serveur qui écoute sur le port 3000 et répond "Bonjour depuis le serveur !" à quiconque visite http://localhost:3000.

Routes : associer une adresse à une réponse

Une route associe une méthode HTTP (vue en Phase 00) et une adresse à une fonction qui génère la réponse. req (la requête reçue) et res (la réponse à construire) sont les deux objets qu'on manipule dans chaque route.

app.get("/api/villes", (req, res) => { res.json(["Dakar", "Thiès", "Saint-Louis"]); }); app.get("/api/villes/:id", (req, res) => { const id = req.params.id; // la partie dynamique de l'URL res.json({ id, nom: "Dakar" }); });
Définition

req.params contient les parties dynamiques de l'URL (comme :id). res.json(...) envoie une réponse au format JSON — le même format que celui que tu lisais déjà côté client en Phase 01 du parcours IA.

Lire le corps d'une requête

Pour les requêtes POST ou PUT, les données envoyées arrivent dans req.body — à condition d'activer le middleware qui sait lire du JSON.

app.use(express.json()); // indispensable pour lire req.body en JSON app.post("/api/villes", (req, res) => { const nouvelleVille = req.body; console.log("Ville reçue :", nouvelleVille.nom); res.status(201).json(nouvelleVille); });
À retenir
  • Node.js exécute du JavaScript hors navigateur ; npm installe les bibliothèques, dont Express.
  • Express simplifie la création d'un serveur et la définition de routes.
  • Une route associe une méthode HTTP + une adresse à une fonction (req, res) => {...}.
  • req.params lit les parties dynamiques de l'URL, req.body lit les données envoyées (avec express.json() activé).
  • res.json(...) et res.status(...) construisent la réponse.
