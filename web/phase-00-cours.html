Comment marche le web

Avant d'écrire une seule ligne de HTML, comprends ce qui se passe réellement entre le moment où tu tapes une adresse et celui où la page s'affiche. C'est la base sur laquelle tout le reste du parcours repose.

Client et serveur

Le web repose sur une relation simple entre deux rôles : le client (ton navigateur) qui demande quelque chose, et le serveur (un ordinateur ailleurs dans le monde) qui répond.

Définition

Un serveur est un ordinateur toujours allumé et connecté à internet, dont le rôle est d'attendre des demandes et d'y répondre — en général en renvoyant une page, une image ou des données.

Le client envoie une requête, le serveur renvoie une réponse. Toute navigation web repose sur cet aller-retour.

Le rôle du DNS

Un serveur n'a pas de nom, il a une adresse IP — une suite de chiffres comme 142.250.180.14. Comme personne ne retient ça, on utilise des noms de domaine (google.com) à la place. Le DNS (Domain Name System) est l'annuaire qui fait la traduction entre les deux.

Définition

Le DNS transforme un nom de domaine lisible par un humain en adresse IP compréhensible par les machines — un peu comme un annuaire téléphonique pour internet.

Anatomie d'une requête HTTP

Quand ton navigateur contacte un serveur, il utilise le protocole HTTP. Chaque requête a une méthode, une adresse, et parfois des données. Chaque réponse a un code de statut qui indique si tout s'est bien passé.

GET /index.html HTTP/1.1 Host: devyoon.sn User-Agent: Mozilla/5.0 ← réponse du serveur HTTP/1.1 200 OK Content-Type: text/html

Les codes de statut à connaître

  • 200 OK — tout s'est bien passé, voici la ressource
  • 301 / 302 — la ressource a été déplacée
  • 404 Not Found — la ressource demandée n'existe pas
  • 500 Internal Server Error — le serveur a rencontré un problème

Ce qui se passe quand tu tapes une URL

Voici la séquence complète, de la barre d'adresse à l'affichage de la page — c'est exactement ce que ton projet de fin de phase te demandera d'expliquer.

1

Tu tapes l'adresse

Le navigateur identifie le nom de domaine dans l'URL saisie.

2

Résolution DNS

Le navigateur demande au DNS l'adresse IP correspondant à ce nom de domaine.

3

Connexion au serveur

Le navigateur ouvre une connexion vers le serveur à cette adresse IP.

4

Requête HTTP

Le navigateur envoie une requête demandant la page (méthode GET en général).

5

Réponse du serveur

Le serveur renvoie un code de statut et, si tout va bien, le contenu HTML de la page.

6

Affichage

Le navigateur lit le HTML, télécharge les ressources liées (CSS, images, JS) et affiche la page.

À retenir
  • Le web fonctionne sur un modèle client/serveur : une requête, une réponse.
  • Le DNS traduit les noms de domaine en adresses IP.
  • Chaque échange HTTP a une méthode, une adresse, et un code de statut.
  • Taper une URL déclenche une séquence précise de six étapes, du DNS à l'affichage final.
