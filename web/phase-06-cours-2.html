Bases de données et SQL

Un serveur Express qui garde ses données dans un simple tableau JavaScript perd tout dès qu'il redémarre. Une vraie application a besoin d'un endroit où les données survivent — une base de données.

Pourquoi une base de données

Les variables JavaScript vivent en mémoire : dès que le serveur s'arrête (crash, redéploiement, simple redémarrage), tout disparaît. Une base de données stocke les données sur disque, de façon structurée, et les garde même si le serveur redémarre.

Définition

Une base de données relationnelle (comme PostgreSQL, MySQL ou SQLite) organise les données en tables — comme des feuilles de calcul, avec des colonnes définies et des lignes qui contiennent les données.

Une table, en pratique

Imagine une table villes pour l'exemple du cours précédent :

Chaque colonne a un type fixe, chaque ligne est un enregistrement — ici, deux villes.

Les quatre opérations de base en SQL

SQL (Structured Query Language) est le langage utilisé pour interroger une base relationnelle. Quatre instructions couvrent le CRUD complet (Create, Read, Update, Delete).

-- Créer une ligne INSERT INTO villes (nom, population) VALUES ('Ziguinchor', 205000); -- Lire des lignes SELECT * FROM villes; SELECT nom FROM villes WHERE population > 300000; -- Modifier une ligne UPDATE villes SET population = 1200000 WHERE nom = 'Dakar'; -- Supprimer une ligne DELETE FROM villes WHERE nom = 'Ziguinchor';
Correspondance avec le CRUD

INSERT ↔ Create, SELECT ↔ Read, UPDATE ↔ Update, DELETE ↔ Delete — c'est exactement le même cycle que celui que ton serveur Express exposera via ses routes, vu au cours 1.

Connecter Express à une base

En pratique, on utilise rarement du SQL brut dans le code — un ORM (Object-Relational Mapping) permet de manipuler les données avec des objets JavaScript plutôt que des chaînes SQL.

// Exemple avec un ORM (syntaxe simplifiée, à titre d'illustration) const villes = await Ville.findAll(); const nouvelle = await Ville.create({ nom: "Kaolack", population: 230000 }); await Ville.update({ population: 1200000 }, { where: { nom: "Dakar" } });
À savoir pour plus tard

Des bases comme SQLite (fichier local, parfaite pour apprendre et pour de petits projets) ou PostgreSQL (plus robuste, utilisée en production) sont les choix les plus courants pour un projet Node/Express. On ne les installe pas ici — l'essentiel de cette phase est de comprendre le principe.

À retenir
  • Une base de données garde les données sur disque, contrairement à une variable en mémoire.
  • Une base relationnelle organise les données en tables (colonnes fixes, lignes de données).
  • SQL couvre le CRUD avec quatre instructions : INSERT, SELECT, UPDATE, DELETE.
  • Un ORM permet de manipuler les données avec des objets JavaScript plutôt que du SQL écrit à la main.
