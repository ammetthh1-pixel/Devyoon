État, listes et assemblage

Dernier cours de la phase : l'état, ce qui rend un composant vraiment interactif, puis comment afficher des listes de données proprement — les deux ingrédients qui manquent pour construire ton projet.

useState : donner une mémoire à un composant

Un composant a besoin de retenir des informations qui changent dans le temps — un compteur, une liste, un filtre actif. C'est le rôle du hook useState.

const { useState } = React; function Compteur() { const [valeur, setValeur] = useState(0); return ( <div> <p>Compteur : {valeur}</p> <button onClick={() => setValeur(valeur + 1)}>+1</button> </div> ); }
Définition

useState(valeurInitiale) renvoie une paire : la valeur actuelle, et une fonction pour la modifier. Appeler cette fonction déclenche automatiquement un nouveau rendu du composant avec la valeur à jour — jamais modifier directement la variable d'état.

Un hook est une fonction spéciale de React (toujours préfixée use) qui donne accès à des fonctionnalités comme l'état, appelable uniquement à l'intérieur d'un composant.

État avec un tableau ou un objet

L'état peut contenir une structure complète, comme une liste de tâches. La règle à retenir : on ne modifie jamais un tableau ou un objet d'état directement — on en crée toujours un nouveau.

const [taches, setTaches] = useState([ { id: 1, texte: "Réviser React" } ]); // Ajouter une tâche : on crée un NOUVEAU tableau, on ne modifie pas l'ancien function ajouterTache(texte) { setTaches([...taches, { id: Date.now(), texte }]); }
Pourquoi ne pas modifier directement

React détecte les changements en comparant l'ancienne et la nouvelle référence. Modifier le tableau existant (taches.push(...)) garde la même référence — React ne voit alors aucun changement et ne réaffiche rien. Créer un nouveau tableau (avec [...taches, nouvelleTache]) est ce qui déclenche le rendu.

Afficher une liste avec .map()

Pour transformer un tableau de données en une liste de composants, on utilise .map() — la même méthode que tu utilisais déjà en JavaScript pur.

function ListeTaches({ taches }) { return ( <ul> {taches.map((tache) => ( <li key={tache.id}>{tache.texte}</li> ))} </ul> ); }
La prop key

Chaque élément généré par .map() a besoin d'une prop key unique et stable (l'id de la donnée, pas l'index du tableau si la liste peut changer d'ordre). React s'en sert pour savoir quel élément a changé, a été ajouté ou supprimé, sans tout redessiner.

Affichage conditionnel

Afficher quelque chose différemment selon l'état se fait avec les outils JavaScript habituels — une expression ternaire, ou l'opérateur &&.

function Statut({ estConnecte }) { return ( <div> {estConnecte ? <p>Bienvenue !</p> : <p>Connecte-toi.</p>} {estConnecte && <button>Se déconnecter</button>} </div> ); }

C'est exactement ce mécanisme qui permet de construire "plusieurs vues" dans une seule application : un état qui indique la vue active, et un rendu conditionnel qui affiche la bonne partie de l'interface en fonction.

Tout assembler

Un exemple qui combine état, liste et affichage conditionnel — la structure que ton projet va reprendre et compléter.

function App() { const [taches, setTaches] = useState([ { id: 1, texte: "Réviser", terminee: false } ]); const [filtre, setFiltre] = useState("toutes"); const visibles = taches.filter((t) => filtre === "toutes" ? true : t.terminee === (filtre === "terminees") ); return ( <div> <button onClick={() => setFiltre("toutes")}>Toutes</button> <ul> {visibles.map((t) => <li key={t.id}>{t.texte}</li>)} </ul> </div> ); }
À retenir
  • useState donne à un composant une valeur qu'il peut modifier, en déclenchant un nouveau rendu.
  • On ne modifie jamais un tableau/objet d'état directement — on en crée un nouveau à chaque mise à jour.
  • .map() transforme des données en composants ; chaque élément a besoin d'une key unique et stable.
  • Le rendu conditionnel (ternaire, &&) permet de construire plusieurs "vues" dans une seule application.
