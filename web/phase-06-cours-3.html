Construire une API REST complète

Routes, requêtes, base de données : il manque la convention qui rend tout ça cohérent et prévisible pour quiconque utilise ton API. C'est ce que REST apporte — et c'est exactement la structure que ton projet va reproduire.

Le principe REST

REST (Representational State Transfer) est un ensemble de conventions pour organiser une API autour de ressources (des entités comme "une ville", "une tâche") et de méthodes HTTP qui décrivent l'action voulue sur cette ressource.

La convention REST
ActionMéthodeAdresse
Lister toutes les ressourcesGET/items
Lire une ressource préciseGET/items/:id
Créer une ressourcePOST/items
Modifier une ressourcePUT/items/:id
Supprimer une ressourceDELETE/items/:id

L'adresse ne contient jamais le verbe d'action (pas de /getItems ou /deleteItem) — c'est la méthode HTTP qui porte l'intention, l'adresse ne décrit que la ressource.

Codes de statut pour chaque cas

Au-delà de 200 et 404 vus en Phase 00, une API REST bien conçue distingue plus précisément les cas :

  • 200 OK — lecture ou modification réussie
  • 201 Created — création réussie (réponse à un POST)
  • 204 No Content — suppression réussie, rien à renvoyer
  • 400 Bad Request — la requête envoyée est mal formée
  • 404 Not Found — la ressource demandée n'existe pas
  • 500 Internal Server Error — une erreur côté serveur

Exemple complet : une API de tâches

En combinant tout ce qui précède, voici une API CRUD complète pour des tâches — le même modèle de données que ton tout premier projet IA, mais exposé en HTTP cette fois.

const express = require("express"); const app = express(); app.use(express.json()); let taches = [{ id: 1, texte: "Réviser", terminee: false }]; let prochainId = 2; app.get("/api/taches", (req, res) => res.json(taches)); app.post("/api/taches", (req, res) => { const tache = { id: prochainId++, texte: req.body.texte, terminee: false }; taches.push(tache); res.status(201).json(tache); }); app.put("/api/taches/:id", (req, res) => { const tache = taches.find(t => t.id === Number(req.params.id)); if (!tache) return res.status(404).json({ erreur: "Introuvable" }); tache.terminee = req.body.terminee; res.json(tache); }); app.delete("/api/taches/:id", (req, res) => { taches = taches.filter(t => t.id !== Number(req.params.id)); res.status(204).send(); }); app.listen(3000);

Appeler cette API depuis le front

Côté client (ton app React ou JS vanille), c'est exactement fetch() — vu en Phase 01 du parcours IA pour consommer une API externe, utilisé ici pour parler à ta propre API.

const reponse = await fetch("/api/taches", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ texte: "Nouvelle tâche" }) }); const tache = await reponse.json();
À retenir
  • REST organise une API autour de ressources ; l'action vient de la méthode HTTP, pas de l'adresse.
  • 201 pour une création, 204 pour une suppression réussie sans contenu, 404 pour une ressource absente.
  • Un serveur Express complet combine routes, lecture de req.body/req.params, et une structure de données (en mémoire ou en base).
  • Le front appelle cette API avec fetch(), exactement comme pour une API externe.
