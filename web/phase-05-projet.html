Tes tâches, en React

Reprends l'idée de la liste de tâches, cette fois avec des composants, des props et de l'état — et une vraie fonctionnalité de filtrage par vue (Toutes / En cours / Terminées).

Objectif

Le code de départ contient déjà la structure générale de l'application (composants App et Tache, état, boutons de filtre) — à toi de compléter les parties manquantes pour la rendre fonctionnelle.

Ce qu'il te reste à faire

Composant Tache — affiche le texte de la tâche reçue en prop, avec une classe terminee si elle est marquée comme telle

Filtrage réel — calcule la liste affichée à partir de l'état filtre, avec .filter()

Transmission des props — passe chaque tâche au composant Tache, avec une key unique

Contraintes techniques

  • Utilise useState pour l'état des tâches et l'état du filtre — déjà amorcés dans le code de départ
  • Le composant Tache doit être séparé et recevoir ses données via des props, pas en accédant directement à une variable globale
  • Chaque élément de la liste a besoin d'une key unique (l'id de la tâche)
  • Le filtrage doit vraiment utiliser .filter() sur l'état des tâches, pas une liste réécrite en dur
Comment fonctionne cet éditeur pour React

Un troisième onglet est apparu : script.js, où s'écrit ton JSX. Il est transformé dans le navigateur par Babel (chargé automatiquement) — pas de build, pas d'installation. C'est une simplification pédagogique : un vrai projet React en production passerait par un outil comme Vite.

Critère de réussite

Les tâches s'affichent avec leur texte, la tâche marquée terminée apparaît visuellement différente, et le code de filtrage utilise réellement l'état sélectionné — pas une liste statique qui ignore les boutons.
